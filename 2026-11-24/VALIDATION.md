## 验证方式

我在 macOS ARM64、Edge 158、2x 显示比例下，用 Release 编译的采集代码运行真实 `CGEvent → ScreenCaptureKit → ScrollCapturer → 拼接及补尾帧` 链路。测试窗口与浏览器配置独立于日常使用环境。

为了避免测试程序吞掉键盘输入，我只在临时诊断副本中关闭了全局输入拦截，并在内存中保留采集帧，结束后才写盘。自动滚动、采屏、缩略图、拼接和收尾仍使用对应本轮 `fc35f1d` 修复的生产代码。

## 内容完整度如何检查

我按标题编号和空间位置检查 001–060 是否依次出现，并检查同号正文位于该标题与下一个标题之间，避免只数标题却漏掉行内错接。

分块 OCR 的重叠区域可能把同一行识别两遍。我的合并规则是：编号相同、纵向坐标相差小于 20px、横向坐标相差小于 30px。原始 OCR 识别结果保留不变。统计文件的 `ocrSameRowMerges` 记录了本次七组重叠，它们的纵向坐标只相差约 0.919–2.047px，均属于同一行，不是图中真的重复了正文。

## 如何使用测试页面

1. 在本目录启动静态文件服务，或用浏览器打开 [index.html](index.html)
2. 选择“吸顶网页”“手动滚动”或“固定聊天输入栏”，先点击“回到顶部并清零”
3. 用 capcap 框选页面左侧标明的 800×550 CSS 像素区域，避免包含右侧统计面板，再启动对应滚动模式
4. 检查成图编号、固定栏和末尾内容；通过页面“导出 JSON”保存浏览器事件以作对照

`index.html` 是自建原始测试页面，不会自行控制 capcap。复现完整自动采集仍需要启动应用的滚动截图功能。
